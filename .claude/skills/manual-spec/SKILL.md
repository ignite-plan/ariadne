# 기획서 요약 (최신화 1단계)

사람에게 묻지 않고 끝까지 진행한다. **매뉴얼 파일은 고치지 않는다.** 할 일은 요약 JSON 파일 하나를 쓰는 것뿐이다.

## 입력 (프롬프트 끝 "이번 작업")
- 매뉴얼 id, 메뉴(장) 이름, 대상 화면 파일 목록, 요약 파일 경로, 지난 요약의 근거 문서와 버전(있으면)

## 도구
- Confluence 읽기 도구. **쓰기는 하지 않는다**
- Read/Glob/Grep, 요약 파일 경로에만 Write. STG 도구는 쓰지 않는다

## 1. 근거 문서 찾기 (스페이스 DLRS)
- 화면 기획서는 `[YYYYMMoutput][Phase3][BO|FO] <메뉴> 화면`. 월별로 여러 개면 **가장 최근 output** 하나
- 그 기획서 머리에서 가리키는 정책 문서
- 검색 결과의 제목·id·버전만으로 고를 수 있으면 본문을 열기 전에 고른다

## 2. 지난 요약과 같으면 멈춘다
지난 요약이 주어졌고, 1에서 고른 문서 id와 버전이 **모두 같으면** 파일을 쓰지 않고 마지막 응답만 한다 (`"reused": true`). 앱이 지난 요약을 그대로 쓴다.

## 3. 읽고 요약하기
- 큰 문서는 결과가 파일로 떨어진다. 화면 단위로 필요한 곳만 Grep/Read로 본다 (같은 파일을 처음부터 반복해서 읽지 않는다)
- 문서 히스토리 표의 최근 변경(날짜, 티켓, 변경 내용)을 먼저 본다
- 대상 화면 파일은 첫 20줄(front-matter와 제목) 정도만 읽어 어느 기획서 화면인지 맞춘다

화면마다 다음을 영어 라벨 그대로, 화면당 1500~3000자 안에서 적는다:
- 항목(필드/컬럼)과 버튼 이름, 필수 여부, 최대 길이·형식, 기본값
- 노출 조건, 권한, 상태별 동작, 팝업/탭/상세로 이어지는 흐름
- 최근 변경 (날짜, 티켓, 무엇이 바뀌었는지)
- 기획서에서 미결/검토 중인 것은 "(미결)"로 표시
- 근거 문서 제목을 문장 끝 괄호로

여러 화면에 걸친 정책(권한 체계, 공통 메시지 등)은 `common`에 한 번만 적는다.

## 4. 파일 쓰기
요약 파일 경로에 Write로 JSON을 쓴다. `screens`의 키는 대상 화면 파일 경로 그대로:

```json
{
  "menu": "Menu Management",
  "generatedAt": "2026-10-03T09:00:00Z",
  "pages": [{ "id": "536957869", "title": "[202606output][Phase3][BO] 메뉴 관리 화면", "version": 12, "url": "https://hmg.atlassian.net/wiki/spaces/DLRS/pages/536957869" }],
  "common": "…",
  "screens": { "08-menu-management/01-menu-list-view.md": "…" }
}
```
- `version`은 Confluence 페이지 버전 숫자
- 기획서에서 대상 화면을 못 찾았으면 그 화면은 `"(기획서에 없음)"`

## 5. 마지막 응답
한두 줄 한국어 요약 뒤에 JSON 블록 하나로 끝낸다:

```json
{ "sections": [], "reused": false, "sources": [{ "title": "…", "url": "…", "version": "12" }] }
```
