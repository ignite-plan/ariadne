# 기획서 요약 (최신화 1단계)

사람에게 묻지 않고 끝까지 진행한다. **파일은 쓰지 않는다** (쓰기 도구가 없다). 요약은 마지막 응답의 JSON 블록으로 내고, 앱이 그것을 저장한다.

## 입력 (프롬프트 끝 "이번 작업")
- 매뉴얼 id, 메뉴(장) 이름, 대상 화면 파일 목록, 지난 요약의 근거 문서와 버전(있으면)

## 도구
- Confluence 읽기 도구. **쓰기는 하지 않는다**
- Read/Glob/Grep (읽기만). STG 도구는 쓰지 않는다
- 큰 문서를 Read로 통째로 읽으면 토큰 한도에 걸린다. 처음부터 Grep이나 Read의 offset/limit으로 필요한 곳만 본다

## 1. 근거 문서 찾기 (스페이스 DLRS)
- 화면 기획서는 `[YYYYMMoutput][Phase3][BO|FO] <메뉴> 화면`. 월별로 여러 개면 **가장 최근 output** 하나
- 그 기획서 머리에서 가리키는 정책 문서
- 검색 결과의 제목·id·버전만으로 고를 수 있으면 본문을 열기 전에 고른다

## 2. 지난 요약과 같으면 멈춘다
지난 요약이 주어졌고, 1에서 고른 문서 id와 버전이 **모두 같으면** 본문을 읽지 말고 바로 끝낸다. 마지막 응답의 JSON 블록은 `{ "reused": true }` 하나. 앱이 지난 요약을 그대로 쓴다.

## 3. 읽고 요약하기
- 큰 문서는 결과가 파일로 떨어진다. 화면 단위로 필요한 곳만 Grep/Read로 본다 (같은 파일을 처음부터 반복해서 읽지 않는다)
- 문서 히스토리 표의 최근 변경(날짜, 티켓, 변경 내용)을 먼저 본다
- 대상 화면 파일은 첫 20줄(front-matter와 제목) 정도만 읽어 어느 기획서 화면인지 맞춘다

화면마다 다음을 영어 라벨 그대로, 화면당 1500~3000자 안에서 적는다:
- 항목(필드/컬럼)과 버튼 이름, 필수 여부, 최대 길이·형식, 기본값
- 노출 조건, 권한, 상태별 동작, 팝업/탭/상세로 이어지는 흐름
- 최근 변경 (날짜, 티켓, 무엇이 바뀌었는지)
- 기획서에서 미결/검토 중인 것은 "(미결)"로 표시
- 근거 문서 제목을 문장 끝 괄호로

여러 화면에 걸친 정책(권한 체계, 공통 메시지 등)은 `common`에 한 번만 적는다.

## 막히면 표시하고 넘어간다 (헛돌지 않기)
- 큰 기획서 결과 파일은 Grep에 앞뒤 줄(-B/-A 또는 -C)을 넉넉히 줘서 **한 번에** 본다. 같은 패턴·같은 구간을 다시 찾지 않는다 (앱은 같은 조회를 되풀이하면 작업을 멈춘다)
- 문서 히스토리 표는 셀이 합쳐져 날짜가 다른 줄에 있을 수 있다. 행 하나를 3번 넘게 다시 찾지 않는다. 날짜가 애매하면 티켓 번호로 판단하고, 그래도 모르면 `(날짜 불명확 — 확인 필요)`라고 적고 다음 행으로 넘어간다
- 다 확인하지 못했더라도 **반드시 마지막 JSON을 낸다**. 모르는 곳은 `(확인 필요)`로 적는다. JSON 없이 끝나면 앱은 요약을 받지 못한다

## 반영 범위가 있을 때 (이번 작업에 "반영 범위"가 있으면)
- 기간의 끝 달이 있으면 그 달 또는 그 전 output 중 가장 최근 것만 근거로 쓴다. 그 뒤 output은 보지 않는다
- Jira 티켓이 있으면 `jira_get_issue`로 제목·설명을 읽고, 기획서 문서 히스토리에서 그 티켓 번호가 붙은 변경을 찾는다
- 문서 히스토리에서 **기간 안 날짜이거나 입력한 티켓에 해당하는 변경만** 골라 화면별로 나눈다. 범위 밖 변경은 적지 않는다
- `screens`는 평소처럼 그 output 기준 화면 요약, 그리고 `changes`에 화면 → 이번에 반영할 변경을 적는다 (무엇이 어떻게 바뀌었는지, 날짜, 티켓 번호). 반영할 변경이 없는 화면은 `changes`에서 뺀다
- 지난 요약 재사용(`reused`)은 하지 않는다

## 4. 마지막 응답
한두 줄 한국어 요약 뒤에 **JSON 블록 하나로** 끝낸다. 앱이 이 블록을 그대로 저장한다. `screens`의 키는 대상 화면 파일 경로 그대로:

```json
{
  "menu": "Menu Management",
  "pages": [{ "id": "536957869", "title": "[202606output][Phase3][BO] 메뉴 관리 화면", "version": 12, "url": "https://hmg.atlassian.net/wiki/spaces/DLRS/pages/536957869" }],
  "common": "…",
  "screens": { "08-menu-management/01-menu-list-view.md": "…" },
  "changes": { "08-menu-management/04-menu-editing.md": "2026-07-14 GIDPDVO-2067: 메뉴 권한에 General(Directory) 타입 추가 — 권한 팝업에 체크박스 …" }
}
```
- `changes`는 반영 범위가 있을 때만 넣는다
- `pages`는 근거로 읽은 문서 전부. `version`은 Confluence 페이지 버전 숫자. 비어 있으면 앱이 요약으로 받지 않는다
- 기획서에서 대상 화면을 못 찾았으면 그 화면은 `"(기획서에 없음)"`
- JSON 안 문자열의 줄바꿈은 `\n`으로 쓴다 (JSON이 깨지면 앱이 요약 없이 진행한다)
