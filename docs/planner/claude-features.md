# Claude로 초안 만들기와 최신화

[← 기획자 사용법](README.md)

Claude가 **Confluence DLRS 기획서 최신 output**과 **실제 STG 화면**을 보고 매뉴얼을 쓰거나 고칩니다.

| 기능 | 언제 | 걸리는 시간 |
|---|---|---|
| [Claude로 초안 만들기](#claude로-초안-만들기) | 매뉴얼에 없는 새 메뉴 | 수 분 ~ 수십 분 (메뉴 크기에 따라) |
| [Claude로 최신화](#claude로-최신화) | 이미 있는 화면을 최신 기획서·화면에 맞출 때 | 화면 하나 수 분 ~ 10분, 장 전체 15~25분 |

> [!IMPORTANT]
> 기획서와 STG 화면이 다르면 Claude가 판단하지 않고 `TODO: 기획서(…)는 A, STG 화면은 B`로 남깁니다. 끝나면 **TODO** 탭과 [Claude 변경 표시](#claude-변경-검토)를 꼭 확인합니다.
>
> 저장, 삭제, 승인, 발송 같은 버튼은 앱이 거절하고(로그에 빨간 줄), STG로 가는 쓰기 요청도 막습니다. 내 Claude 사용량을 씁니다.

## 준비 (한 번만)

| 항목 | 확인 |
|---|---|
| Claude Code | 앱이 앱 전용 버전(H-Chat이 받는 고정 버전)을 받아 둡니다. 없으면 앱을 켤 때 뒤에서 받습니다(약 220MB). 점검 화면에서 노란색(내 PC의 claude)이면 **앱 전용으로 설치** |
| 인증 | 기본은 `~/.zshrc`의 `ANTHROPIC_API_KEY`. 설정 → 고급에서 claude.ai 로그인으로 바꿀 수 있습니다 |
| Confluence 연결 | 내 Claude Code에 Atlassian MCP가 연결되어 있어야 합니다(`claude mcp list`). 앱이 그 설정을 가져다 씁니다 |

Claude 패널의 점검 화면에서 세 가지와 STG 로그인 상태를 한 번에 볼 수 있습니다.

## Claude로 초안 만들기

매뉴얼에 없는 메뉴(예: Menu Management)의 화면 섹션 초안을 씁니다.

1. 목차 아래 **새 화면** → **Claude로 초안 만들기**
2. **메뉴 이름**(영어)과 **장**(새 장이면 이름과 위치)을 고릅니다. STG 경로나 메모를 알려 줄 수도 있습니다(선택).
3. **다음** → 점검 화면에서 Claude Code, Confluence, STG 로그인을 확인합니다. STG 로그인이 없으면 여기서 로그인합니다.
4. **초안 만들기 시작**. Claude가 하는 일이 한 줄씩 나옵니다(기획서 읽기 → STG 화면 열기 → 캡처 저장 → 화면별 섹션 쓰기). 언제든 **중지**할 수 있습니다.
5. 끝나면 만든 화면, 이미지, TODO 수, 참고한 기획서 링크가 나옵니다. **TODO** 탭에서 확인할 곳을 보고 다듬은 뒤 **제출**합니다.

- Claude가 만든 캡처 정의(`shots.ts`)가 같이 생겨서, 다음부터 **캡처** 버튼으로 다시 찍을 수 있습니다.
- 이미 매뉴얼에 있는 메뉴는 새로 만들지 않습니다. 그때는 [Claude로 최신화](#claude로-최신화)를 씁니다.
- 장 전체의 문체를 맞추려고 Claude 하나가 화면을 순서대로 씁니다.
- 마음에 들지 않으면 **변경** 탭의 **모두 되돌리기**로 지우고 다시 만듭니다.

## Claude로 최신화

이미 있는 화면을 최신 기획서와 STG 화면에 맞춰 고칩니다. 바뀐 곳만 고치고, 근거가 다르면 TODO로 남깁니다.

### 시작하기

| 시작하는 곳 | 대상 |
|---|---|
| 문서 위쪽 **✦ Claude로 최신화** | 지금 화면 |
| 목차에서 화면에 마우스를 올리고 **✦** | 그 화면 |
| 목차에서 장에 마우스를 올리고 **✦** | 장 전체 |

1. 점검 화면을 확인하고 **최신화 시작**을 누릅니다.
2. 먼저 최신 기획서를 한 번 요약하고, 화면을 **3개씩 동시에** 확인합니다.
3. 로그 위 화면 목록에서 화면별 진행(대기 / 진행 중 / 고침 / 바꿀 것 없음 / 건너뜀 / 실패)을 봅니다. 화면을 누르면 그 화면의 로그만 보입니다.
4. 끝나면 **고친 화면 / 그대로인 화면 / 건너뛴 화면**이 나옵니다. 고친 화면을 누르면 그 화면의 첫 변경 위치가 열립니다.
5. [변경을 검토](#claude-변경-검토)하고, 마음에 들지 않는 화면은 **변경** 탭에서 ↺로 되돌린 뒤 나머지를 **제출**합니다.

### Claude 변경 검토

Claude가 고친 화면은 목차에 `검토` 표시가 붙고, 화면을 열면 위쪽에 **Claude 변경** 막대가 나옵니다.

| 어디서 | 어떻게 보이나 |
|---|---|
| 미리보기 | Claude가 넣은 글자는 초록 밑줄, 지운 글자는 빨간 취소선 (완성 문서 모양 그대로, 단어 단위) |
| 편집기 | 바뀐 줄 왼쪽에 막대 |
| Claude 변경 막대 | ↑ ↓로 변경 사이 이동, **검토 완료**로 표시 끄기 (내용은 그대로) |

- 비교 기준은 Claude가 고치기 직전 본문이라, 내가 전에 고친 내용과 섞이지 않습니다. 검토 전에 같은 화면을 다시 최신화해도 처음 원문과 비교합니다.
- 제출하거나 되돌리면 표시가 사라집니다.

> [!NOTE]
> 이 표시는 앱 화면에만 보이고 매뉴얼 파일이나 Word에는 들어가지 않습니다. 노란 형광펜(Word로 나가는 서식)과는 다른 기능입니다.

### 대기열

최신화가 도는 동안 다른 화면이나 장의 ✦를 누르면 **대기에 추가 (N번째)**로 걸어 둘 수 있습니다(반영 범위도 함께 저장). 앞 작업이 끝나면(성공, 실패, 중지 모두) 다음 대기 작업이 자동으로 시작합니다.

- 위쪽 작업 표시에 `대기 N`이 보입니다.
- 진행 패널의 **대기 중인 최신화**에서 ↑ ↓로 순서를 바꾸거나 빼고, **모두 비우기**로 비웁니다.
- **끝난 작업**에서 앞서 끝난 작업의 결과를 다시 엽니다.
- 대기 작업을 시작하기 전에 STG 로그인을 확인합니다. 만료됐으면 대기열이 **멈춤**이 되니 다시 로그인한 뒤 **계속**을 누릅니다.

> [!WARNING]
> 대기열은 앱을 켜 둔 동안만 유지됩니다. 작업 중이거나 대기가 있을 때 앱을 끄면 확인 창이 뜹니다. 초안 만들기와 영상 Claude 작업은 대기할 수 없습니다(한 번에 하나).

### 반영 범위

특정 기간이나 Jira 티켓의 변경만 반영하려면 시작 전에 패널의 **반영 범위**에 넣습니다.

| 입력 | 예 |
|---|---|
| 기간 | `2026-05 ~ 2026-08` |
| 티켓 | `GIDPGRO-973, GIDPDVO-2067` |

- 끝 달까지의 output만 근거로 쓰고, 문서 히스토리에서 그 기간이나 티켓의 변경만 골라 반영합니다. 해당 변경이 없는 화면은 건너뜁니다.
- STG에는 범위 뒤 변경이 이미 들어가 있을 수 있어 **캡처 이미지는 다시 찍지 않습니다**. 이미지나 화면이 범위와 맞지 않는 곳은 TODO로 남습니다.
- 일부만 반영한 것이라 `refreshedFrom`(아래)은 남기지 않습니다. 나중에 전체 최신화를 돌리면 다시 확인 대상이 됩니다.

### 알아 두면 좋은 것

- **기획서가 그대로인 화면은 건너뜁니다.** 최신화한 화면 파일에 근거 기획서 버전(`refreshedFrom`)이 남기 때문입니다. 그래도 다시 보려면 **기획서가 안 바뀐 화면도 다시 확인**을 켭니다. 이 기록도 함께 제출하세요.
- 처음 최신화하는 화면은 Claude가 **자동 캡처 정의**도 채웁니다. 다음부터는 **캡처** 버튼으로 그 화면 이미지를 다시 찍을 수 있습니다.
- 설정 → 고급에 dealerhub-web 경로가 있으면(개발자 PC), 코드 연결 키(sources, i18nPrefix)도 채웁니다. 코드는 읽기만 합니다.
- 장 전체 최신화는 처음에 15~25분쯤 걸리고, 기획서가 그대로면 몇 분 안에 끝납니다.
